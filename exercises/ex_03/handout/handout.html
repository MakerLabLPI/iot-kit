The Traitor's Game BME M2 · Session 4 · Lab 3 — ESP32, buttons, MQTT

A live tournament. Every round the game master pairs you with another board. You press Cooperate or Betray; your board gets your points back; the wall shows everything. Your job: make your ESP32 join, play, and light an LED with the result.

Rules

YouOpponentYou getThey get
CooperateCooperate33
BetrayBetray11
BetrayCooperate50
CooperateBetray05
  • Open, 30 s: pairings are on the wall, press your button. The clock runs the full 30 s for everyone.
  • Reveal, 30 s: all moves and points shown at once. Then the next round opens by itself.
  • Only your first press of a round counts. Presses while the round is closed are ignored.
  • No press before the clock ends → a random move for you (dice badge on the wall).
  • Miss 2 rounds in a row → you are dropped. Reset your board (it joins again) to come back; your score is kept.
  • Odd number of players → one sits out that round, in turn.
  • Ranking is by total points: a board that works early scores more rounds.

Your name

Pick a nickname: it is shown on the wall and it is your identity on the broker (the topic path is the only thing that tells the game who pressed).

  • Letters, digits, - and _ only. No spaces, no accents.
  • Unique in the room. Case matters: Alan and alan are two players.
  • Max 24 characters. A wrong name shows as a red line on the wall.

Topics

TopicWho sendsPayloadWhen
bme/s04/game/NAME/joinyour boardanything, e.g. hionce, at the end of setup()
bme/s04/game/NAME/moveyour boardC or Bon a button press, during Open
bme/s04/game/NAME/resultthe game master0, 1, 3 or 5after each round you played — subscribe to it

Everything your board sends appears on the wall within a second, even between rounds: a join is a cyan line, a move a white one, an ignored move a grey one, a mistake a red one. That is how you know your board works. result is points, not a verdict: points >= 3 is good news.

Putting it together

  1. Start from your Lab 2b sketch. Add NAME and the three topic strings at the top.
  2. In setup(), after connecting: subscribe to your result topic, publish on your join topic. Watch your name appear on the wall.
  3. In loop(): read the buttons, publish C or B on your move topic. Watch the line appear on the wall, then "Locked in" on your card.
  4. In the callback: turn the payload into a number, light the good LED if points >= 3, the bad one otherwise, switch off after 1 s without delay().
  5. Done early? Replace delay(200) with a millis() debounce. Remember your own move and show all four outcomes. Think about a strategy: your last result tells you what your opponent did (3 or 0: they cooperated).

Cheat sheet

WiFi

#include <WiFi.h>

WiFi.begin("iot-kit", "SuperStrongPassword1234");
while (WiFi.status() != WL_CONNECTED) delay(500);
WiFi.setSleep(false);   // radio awake: messages arrive at once
Serial.println(WiFi.localIP());

MQTT (PubSubClient)

#include <PubSubClient.h>
WiFiClient net;
PubSubClient client(net);

// in setup(), after WiFi:
client.setServer("192.168.50.1", 1883);
client.setCallback(onMessage);      // who handles received messages
while (!client.connect(NAME)) delay(500);  // client id: unique
client.subscribe("bme/s04/game/Sev/result");
client.publish("bme/s04/game/Sev/join", "hi");

// in loop(), every time, never block for long:
client.loop();                      // receives, keeps the link alive
if (!client.connected()) { /* reconnect */ }

Build a topic from your name

const char* NAME = "Sev";
String topicMove = String("bme/s04/game/") + NAME + "/move";
client.publish(topicMove.c_str(), "C");   // String -> char*

Receiving: the callback

void onMessage(char* topic, byte* payload, unsigned int len) {
  String msg;
  for (unsigned int i = 0; i < len; i++) msg += (char)payload[i];
  int points = msg.toInt();        // "3" -> 3
  // keep it short: no delay(), no publish() in here
}

Serial monitor

Serial.begin(115200);               // in setup()
Serial.println("joined");
Serial.print("points: "); Serial.println(points);
Serial.printf("got %d points\n", points);

Arduino IDE: Tools → Serial Monitor, set 115200 baud. Printing is your first debugging tool.

Buttons

const int BTN = 32;             // button between pin and GND
pinMode(BTN, INPUT_PULLUP);     // in setup()
if (digitalRead(BTN) == LOW) {  // LOW = pressed (pull-up!)
  ...
  delay(200);                   // crude debounce, blocks 200 ms
}

The BOOT button of the dev board is on GPIO 0, also active LOW. Do not hold it while the board resets (that is flashing mode).

LEDs without delay()

const int LED = 25;             // LED + resistor to GND
unsigned long ledOffAt = 0;
pinMode(LED, OUTPUT);           // in setup()

digitalWrite(LED, HIGH);        // switch on...
ledOffAt = millis() + 1000;     // ...and remember when to stop

// in loop():
if (ledOffAt && millis() > ledOffAt) {
  digitalWrite(LED, LOW);
  ledOffAt = 0;
}

On-board blue LED: GPIO 2 on most ESP32-WROOM-32 dev boards.

Debounce with millis() (extension)

unsigned long lastPress = 0;
if (digitalRead(BTN) == LOW && millis() - lastPress > 300) {
  lastPress = millis();
  client.publish(topicMove.c_str(), "C");
}
Nothing on the wall? Check the Serial monitor first: WiFi connected? Broker connected? Then check the topic, character by character — a typo in bme/s04/game/ is the usual suspect. Grey line "ignored — round closed": press during Open. Red line: wrong payload or wrong name. LED never lights: did you subscribe, and is client.loop() called in loop()?

Everything on this network is open: no password on the broker, every message readable by everyone. Keep that in mind until the end of the session.
